# آني | ANI — بداية مشروع تطبيق اجتماعي

هذا مستودع بداية فعلي مبني بـ Flutter وFirebase، وليس خدمة اجتماعية مكتملة على مستوى Instagram/TikTok/X. يحتوي على مصادقة بريد إلكتروني، ملف شخصي، تعديل بعض بيانات الملف، نشر صورة مع وصف، خلاصة، إعجابات، تعليقات، بحث بسيط، قواعد Firestore/Storage أولية، ووظيفة خلفية لإشعار مالك المنشور عند التعليق.

## قبل التشغيل

1. ثبّت Flutter وDart وAndroid Studio أو Xcode حسب المنصة.
2. أنشئ مشروع Firebase جديداً باسم يناسب تطبيق ANI.
3. من Firebase Console فعّل:
   - Authentication > Email/Password.
   - Cloud Firestore.
   - Cloud Storage.
4. ثبّت Firebase CLI وFlutterFire CLI:
   ```bash
   npm install -g firebase-tools
   dart pub global activate flutterfire_cli
   firebase login
   ```
5. من مجلد المشروع:
   ```bash
   flutterfire configure
   ```
   هذا ينشئ `lib/firebase_options.dart`، ثم عدّل `lib/main.dart` لاستعماله كما يوضح قسم الإعداد أدناه.
6. انشر قواعد Firestore وStorage بعد مراجعتها:
   ```bash
   firebase deploy --only firestore:rules,storage
   ```
7. شغّل:
   ```bash
   flutter pub get
   flutter run
   ```

## تهيئة Firebase في main.dart

لأن بيانات Firebase خاصة بمشروعك ولا يجوز اختلاقها، يبدأ الملف باستخدام `Firebase.initializeApp()` من الإعدادات الأصلية للمنصة. بعد تشغيل `flutterfire configure`، يُفضّل تعديل الاستيراد والتهيئة إلى:

```dart
import 'firebase_options.dart';
// ...
await Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform);
```

## إعدادات Android وiOS

- Android: تأكد من وجود `google-services.json` ضمن `android/app/` وإعداد Gradle بواسطة FlutterFire.
- iOS: تأكد من وجود `GoogleService-Info.plist` في Runner وإعدادات Xcode المطلوبة.
- صلاحيات الصور/الكاميرا قد تتطلب إعدادات المنصة. لا تطلب صلاحيات لا يحتاجها المستخدم.

## ما الذي يعمل في هذا الإصدار؟

- إنشاء حساب بالبريد وكلمة مرور، وتسجيل الدخول والخروج.
- إرسال رسالة تحقق بالبريد عند إنشاء الحساب.
- استعادة كلمة المرور عبر البريد.
- حجز اسم المستخدم عبر معاملة Firestore لمنع حجزه مرتين في تدفق التسجيل.
- حفظ الملف الشخصي وتعديل الاسم والنبذة والمدينة والخصوصية.
- اختيار صورة من الجهاز ورفعها إلى Firebase Storage ثم حفظ المنشور في Firestore.
- خلاصة المنشورات، إعجاب/إلغاء إعجاب، التعليقات، البحث البسيط، وعرض الإشعارات التي تنشئها الخدمة الخلفية.
- وظائف خلفية نموذجية لإنشاء إشعار عند التعليق.

## غير مكتمل ولا يجوز تسويقه على أنه جاهز

- تسجيل الدخول برقم الهاتف: يجب بناء شاشة Phone Auth واستكمال إعداد مزود SMS واختباره في Firebase.
- الرسائل الخاصة الفعلية، مكالمات الفيديو/الصوت، القصص ذات انتهاء 24 ساعة، الفيديو القصير مع معالجة/ترميز، البث المباشر.
- طلبات المتابعة للحسابات الخاصة مطبقة جزئياً فقط؛ البحث الحالي يكتب علاقة متابعة مباشرة ولا يفرض دورة طلب/قبول كاملة.
- حظر المستخدمين وفرضه على جميع الاستعلامات، الحفظ، الإشارات، مشاركة المنشورات، وخوارزمية توصية.
- حذف الحساب مع تنظيف كامل للوسائط والبيانات، تنزيل البيانات، لوحة الإدارة، ومراجعة البلاغات.
- إشعارات Push على الجهاز، رموز FCM، إدارة الإذن والإرسال.
- اختبار أمني مستقل، اختبارات تكامل، ومراجعة قواعد الإنتاج.
- رفع الفيديوهات: قواعد التخزين الحالية تسمح بالصور فقط.

## تنبيهات أمنية مهمة

قواعد الأمان المرفقة نقطة بداية يجب مراجعتها قبل إطلاق عام. حالياً قراءة المستخدمين والمنشورات متاحة لأي مستخدم مسجل الدخول، وميزة الخصوصية في الملف الشخصي لا تفرض تلقائياً حجب المحتوى. كما أن علاقة المتابعة تُكتب من العميل في نموذج البحث. لا تطلق التطبيق للعامة قبل تنفيذ صلاحيات الحساب الخاص والحظر وطلبات المتابعة عبر قواعد/وظائف موثوقة، واختبار القواعد باستخدام Firebase Emulator Suite.

لا تضع مفاتيح Admin أو أسرار الخادم في تطبيق Flutter. لا تستخدم حسابات اختبار داخل قاعدة بيانات الإنتاج.

## اختبارات أولية مقترحة

- أنشئ حسابين بالبريدين اللذين تملكهما.
- تحقق من البريدين.
- انشر صورة من الحساب الأول.
- افتح الحساب الثاني وتأكد من ظهور المنشور وفق سياسة الوصول.
- جرّب الإعجاب والتعليق وتحقق من بقاء البيانات بعد إعادة تشغيل التطبيق.
- اختبر قواعد Firestore وStorage باستخدام Emulator Suite قبل النشر.
